# Обновление Help Center: разделы из Heading 1

## Как пользоваться

1. Оставьте один полный документ в одной записи базы Articles в Notion.
2. Сохраните существующие Title, Category, Slug, Status (Ready), Order.
3. Главные разделы оформляйте блоками Heading 1 в основном содержимом страницы.
4. Heading 2/3, таблицы, списки и изображения остаются внутри раздела.
5. Текст до первого Heading 1 выводится как Introduction. Если вступления нет, первым открывается первый раздел.
6. Разделы появляются под названием документа в Product Guide. При открытии статьи показывается только выбранный раздел и оглавление.
7. Существующие группы Market Analysis с отдельными дочерними статьями продолжают работать. Для нового единого документа без дочерних статей разделы формируются автоматически. Старые отдельные записи не объединяются автоматически: исходный полный документ должен находиться в Notion.

Новые свойства базы не нужны. Роли не реализованы и не ограничивают доступ.

## Публикация в существующий GitHub / Vercel проект

Замените исходники в используемой Vercel ветке файлами этого архива, сохранив настройки проекта и переменные NOTION_TOKEN / NOTION_DATABASE_ID в Vercel. Архив не содержит секретов. После проверки preview опубликуйте обычным способом. Рабочий сайт в рамках этой задачи не изменялся.

## Поведение и ограничения

- Граница раздела — Heading 1 верхнего уровня, до следующего Heading 1. Заголовки внутри колонок, toggle и других вложенных блоков не создают самостоятельные разделы.
- Ссылка раздела использует ID блока Heading 1. Переименование сохраняет ссылку; удаление и создание нового заголовка создаёт новый ID. Старый неизвестный ID возвращает 404.
- Сервер получает корневые блоки страницы для построения оглавления (Notion отдаёт их постранично). Вложенные блоки разворачиваются только для выбранного раздела. Это не полная независимая синхронизация документов и не загрузка всего документа в браузер.
- Запросы Notion кэшируются с revalidate 300 секунд. Изменения могут появляться с задержкой, включая время фонового обновления кэша. Нет обещания мгновенной синхронизации.
- Изображения загружаются лениво; долгоживущая копия файлов Notion не создаётся.
- При сбое загрузки блоков показывается ошибка, а не молча обрезанный документ.
- Форматы блоков, которые не поддерживал исходный рендерер, не добавлялись в рамках этой задачи.

## Обновление оформления

Product Guide и Market Analysis используют одинаковые раскрывающиеся карточки документов. По умолчанию карточки закрыты; нажатие на название или стрелку показывает разделы. Строки разделов подсвечиваются при наведении и доступны с клавиатуры. Раскрытие не является отдельным запросом к Notion: оглавления готовятся сервером, содержимое статьи загружается при переходе.

Для автоматической разбивки Market Analysis:
1. Перенесите полный текст в тело основной страницы документа в Notion.
2. Оформите основные заголовки как Heading 1 верхнего уровня.
3. Сохраните Category = Market Analysis, Status = Ready, существующий Slug.
4. Уберите связи Parent article между этим документом и прежними отдельными подстатьями. Снимите с прежних подстатей статус Ready, чтобы они не появились в списке как самостоятельные документы. Не удаляйте их, пока не проверите полноту нового документа.
5. Дождитесь обновления кэша и проверьте разделы. Смена статуса Ready отключит старые адреса подстатей; их автоматическое перенаправление не реализовано.

До этого перехода старые группы продолжают показывать отдельные статьи, но уже в раскрывающихся карточках.

## Legal Documents и Integrations Guide

Добавлены страницы /legal-documents и /integrations-guide с теми же раскрывающимися карточками документов. Они используют Articles: Category = Legal Documents (также поддерживается Legal documents) либо Integrations Guide; Status = Ready; Slug — непустой уникальный адрес; Order — порядок.

Текст документа должен находиться внутри самой страницы Articles. Ссылки на документы на отдельной странице myGaru DataBase сами по себе не добавляют их в Articles. Новые документы и их текст не создавались. Если записей нет, раздел показывает No documents yet. Вступление и Heading 1 обрабатываются так же, как в Product Guide.

## Согласованная выборка документов
Главная и страницы категорий теперь используют один запрос списка Ready с пагинацией и последующей нормализацией категории. Ошибка ответа Notion больше не превращается в пустой список. Проверки: node tests/categories.cjs, node tests/sections.cjs; production-сборка. Это исправление кода не устанавливает причину расхождения в уже опубликованной версии без проверки её исходников и ответов Notion.
